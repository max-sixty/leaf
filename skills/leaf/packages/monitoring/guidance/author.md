Use `lf-monitor` for one active release whose current state, release checks, and run log must stay visible together. Its sole body is an `lf-monitor-grid` containing one `lf-monitor-region` for each `zone`: `release`, `checks`, then `log`. Put the current state, next stage, hold or escalation policy, and rollback consequence in the release region; put named gates with their observed values in checks; bind the changing evidence stream in log. Keep release identity and summary in authored markup so a feed update cannot silently change the page's conclusion. When rollback is genuinely available, put one `lf-release-actions` holder around an `lf-release-action verb="rollback"`; bind the holder to the exact candidate and stable release, and state the consequence in the action's prose. This sends a durable host request and waits for its receipt. Do not present a local choice or decorative button as rollback.
