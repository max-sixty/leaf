Per-token rate limits

Agent brief

The identity change is small and coherent. Authenticated traffic moves from an address-wide collision domain to one bucket per token; untokened traffic keeps an address fallback. Prefixing both keys prevents a token id that resembles an IP address from sharing its bucket.

The patch also makes one behavior change the author description does not call out: bucket lifetime rises from 10 to 30 minutes. That deserves a deliberate answer because it changes cleanup pressure independently of the identity fix. The new schema also lacks restart-level persistence evidence in this packet. I would review the identity path, then the exact patch, then settle those two evidence gates before signing off.

The hot path in four lines

Hover the numbered notes for the two claims that carry the design. The exact implementation appears again in the patch below so every character can be selected and discussed. 

def bucket_key(self, request):
    if request.token:
        return f"tok:{request.token.id}"
    return f"ip:{request.remote_addr}"
A request with both values spends the token budget. This is the change's central policy choice. The tok: and ip: prefixes keep the two identity namespaces from colliding.
