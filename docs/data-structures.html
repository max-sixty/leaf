Data structures

Leaf uses JSON for the state the server sends to the browser, the events in a page's log, and the records stored beside the log. Each table below lists one structure's fields with their types, whether each is required, and what it means.

The tables are generated from the schemas Leaf validates and tests against, so they change when the code does. An event kind's meaning is written once, in Events and threads, which each kind below links to. How the pieces fit together is on How it works.

Served state

The page's runtime reads the state from GET /api/state. The definitions at the end of this section describe JSON responses to POST requests. The user-view and interaction endpoints return no response body. leaf page state prints selected fields from the same state.

Events

Each line of a page's events.jsonl is one event, validated against the schema for its kind before it is appended. The first table lists the fields every kind shares; each kind's table lists the rest.

Records

Leaf keeps these JSON files outside a page's log and document, in the page directory, the machine's state home, or the browser's storage. Each carries a format naming the protocol at which its shape last changed. delivery is the envelope an agent reads with leaf delivery read.

Interaction batch

The browser posts what it observed of the user's session, such as DOM events, to the page's diagnostic trace, observations.jsonl. Nothing in the page's state is read from it.
