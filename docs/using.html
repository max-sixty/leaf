Using a page

Using a Leaf page

An agent hands the user a page about its work. The user reads it, comments on exact passages, makes the choices it asks for, and follows what the agent is doing, by keyboard, pointer or touch.

This guide is for the person working on a page. Pages is for the page's author, and How it works explains the mechanism behind both. Leaf is experimental software. Browser support gaps lists what is known to differ in Chrome, Edge, Firefox and Safari and their mobile versions.

Panel, rail and thread cards

Leaf adds controls around the authored HTML. This interface is called chrome: the Leaf panel floating at the window's foot, comment and decision markers, and thread cards. At rest the panel is one row: the leaf, coloured by the agent's state; the comment field, which shows the agent's status while it is empty; and the On me mark, counting what waits on the user, with a dot while a thread holds a reply they haven't read. The leaf opens a small menu of the page's other controls. Pressing the On me mark opens its view above the row. A ✕ replaces the mark while the view is open and closes it when pressed. A folded panel shows only the leaf in the window's corner.

The On view shows one list at a time, under a tab named for its actor, with completed items under Done, and a Threads tab listing the open threads, then the resolved ones under Resolved. On me and the agent’s list defines their membership. Opening a view preserves the page’s text wrapping and reading position.

The page reserves space at the bottom for the panel's row, so the last lines can scroll above it. A view opens above the row and overlays the page without moving its content. Escape or a press on the page closes the view. Phones and touch screens describes the panel on a touch screen.

The rail is the strip to the right of main where Leaf places comment and decision markers. It appears when the window has enough space: about 960px on a column page or about 1920px on a sidebar page. data-rail="right" keeps it visible above 640px, except on a workspace, whose panes scroll on their own. Where no rail fits, and inside a scrolling pane, a small pin appears beside the target on the page. Leaf places it clear of text and controls when space permits. The o shortcut hides pins and passage highlights.

A thread card opens beside its marker in the margin. If the margin is narrower than the card, it overlaps the text's edge. Threads, a thread opened from it, the On view and All pages open as views above the panel's row, one at a time.

Who can open a page

A page's URL carries an access key, which the browser keeps in a cookie. One key covers every Leaf page on the machine that serves it, so anyone with one page's URL and a network route to that machine can read and act on all of them. A page served on loopback opens only on that machine; one served on an SSH destination or another hostname opens from that network. Leaf opens no public tunnel.

On leaf.page, each browser works on a private copy of a page. Its comments, choices and the hosted agent's revisions are visible to no other browser (The leaf.page website).

Data lifetime

Accepted events and external data survive closing a tab or restarting the server. Browser stores preserve drafts and interface arrangements with the scopes shown below. An update the server has not yet accepted has not reached durable storage; while the status says the connection is lost or the update is not through yet, keep its tab open until it is.

What Reload Close the tab Server restarts Another browser
Picks, drags, and comments accepted into the log ✓ ✓ ✓ ✓
External values, until the next write replaces them ✓ ✓ ✓ ✓
Words the user has typed and not sent ✓ ✓ ✓ ✗
Arrangements of Leaf controls ✓ ✓ ✓ ✗
Reading position, the open tab or panel, design mode ✓ ✗ ✓ ✗

Draft text is shared between tabs showing the same page; arranged controls are shared across pages in that browser. Reading position, the active tab or panel, and design mode belong to one browser tab. Comment text awaiting acceptance remains in the draft store; pending widget actions have no durable browser queue.

Offline exports

leaf page export PAGE -o FILE captures a stamped version, its resources and recorded state in one HTML file. Reading controls and page-owned code work offline; new Leaf choices, comments, Undo and thread interactions need the served page. An agent need not be running to record a choice on a live server. Pages containing live samples cannot export.

Comments and replies

Select a passage, then use the comment control or press c to write a comment. The thread keeps that passage as its anchor. Its marker opens the conversation beside the passage, where the agent's reply and the reply box appear.

The Threads tab of Leaf's On view, which the panel's On me mark opens, lists the threads above the panel's row. Select a thread to read its messages and reply in the panel's comment field. Its passage link returns to the anchor on the page.

A reaction records brief feedback on a passage or agent reply without opening a thread. The default reactions request keeping, changing, clarifying, shortening, supporting, or prioritizing content. Packages can declare additional reactions.

Try a thread

This fictional exchange shows an agent's reply after revising the importer policy. Open the marker beside the sentence to read the exchange, or open Threads in the sample's top row. Select the sentence to try a comment. The sample has its own temporary log; no agent answers its practice comments. Reset restores the fictional exchange.

Anchors

A thread's anchor is the place on the page it is about. The first comment records it in the event log, and that record never changes; a reply or a revision can later move the thread to a new anchor. A comment can be anchored in these ways:

Anchor How the user makes it What the log stores
Passage Select words, then press c section, the id of the nearest element around the words; quote, the words; and prefix and suffix, up to 24 characters on each side
Element ⌥-click (Alt-click) an element, such as an image or a table, or press s and choose one section alone
Part of a picture ⌥-click a box that a diagram declares commentable section and visual, the part's name
Data value Select words inside one value a widget drew from a data source section and datum, the value's key, and for a value from an external source, that source's revision
Drawing Draw on the page in Draw mode (w) An element anchor, plus the strokes
None Press c with nothing selected, or write in the Threads panel's comment box No anchor: the thread is about the whole page

An agent opens threads with the same anchors, using leaf thread create with --quote, --section, --part, or none of them.

How a thread ends

The user usually closes a thread with Resolve thread once they have read the answer. Its marker and ink leave the page, and it moves from Threads' Open list to Resolved. Reopen brings it back, as does z when resolving was the user's latest action.

The agent resolves a thread only when the user asks, or when no review could change the outcome; the thread then reads “Resolved by” and the agent's name. A new message from either side reopens a resolved thread. A reaction, a progress message or a failure notice does not.

z takes back the user's latest action, a message they just sent included: a comment, reply or reaction. A reaction's mark also has an undo control of its own. The log gains an undo naming the message, and the message leaves the page, with any thread it started. Where something has already answered it, it stays in its place instead and reads Deleted. To delete an older message, the user rewrites it to no words.

Words typed but not sent are kept after their box closes. If a new version removes the content they were about, Resume writing (g i) opens them, unsent, in Comment on the page, after any words already there.

Progress on an update and the page

Leaf distinguishes progress on one update from the page’s status. A busy agent has not necessarily started every comment. The agent names the update or to-do it is handling and the work it is doing, in one line. That line appears beside the relevant thread or widget and in the panel; replies carry the results.

A session is the agent conversation attached to the page; a turn is one run within it. The illustrative sequence below follows a request to shorten a lede; its times are examples, not delivery guarantees.

  1. 0s observation Queued for Claude The comment appears in its thread immediately, reading Queued for Claude until the agent has it.
  2. 1s observation Delivered The hook puts the comment into the agent’s turn, and Claude Code's transcript then confirms it reached the agent. Until the agent names its work, the panel shows its leaf in the working tone and no words.
  3. 5s intervention On it The agent says what it is doing: Cutting the lede to two sentences. The comment reads On it, and the same sentence becomes the page’s status.
  4. 1m intervention Each new phase gets a new line When the work moves from editing to checking, the agent starts the same update again: checking the page at phone width.
  5. 2m observation Answered The revision goes live, the agent's reply reports it, and the status returns to Ready — select text to comment.

Stages of an update

A label beside each comment or widget update records its delivery and handling. Leaf changes it only on recorded evidence and clears it when the required answer arrives. Harnesses skip stages they do not report. Only On it, Replying and Answered relay an act of the agent's own, so only they read in its voice; every other label is what Leaf observed of the update, set in italic.

Label Evidence
Queued for Claude No harness has queued the update or put it into the agent's turn. The label is the same while the browser is still sending it and once the server has added it to the page's event log. It names the page's agent and is set in italic, as Leaf's own words are, since the agent can't yet be saying anything about the update.
Up next Codex accepted the update's delivery as the task's next message.
Delivered The agent's harness put the update into the agent's turn. What confirms that differs by harness (Harness connections and receipt); Claude Code can deliver an update again if the turn ends before its transcript shows it.
On it The agent started work on the update and named the work in one line, as a progress message in its thread or with leaf task start, or started a to-do on the update's widget.
Replying On Codex App Server, the turn's answer is streaming into the thread.
Answered (label clears) The answer the update needs is recorded: a reply in its thread, or a version whose markup records the decision.
Delayed, interrupted, or unanswered
Still queued for Claude The update is still queued two minutes after the user sent it.
Stopped The turn the update was delivered into ended, or was interrupted, before the agent answered it.
Gone quiet The agent's start on the update is 15 minutes old, or the turn that wrote it has ended, and the agent has not started the update again. A Delivered update reads the same once nothing shows its turn still running, and so does a Replying reply whose stream disconnects.
Interrupted Codex App Server stopped the turn before it answered.
Not answered The harness gave up on the update: its turn failed, or Leaf could not confirm that the delivery reached a turn. The leaf.page website and the Codex adapter record this.

A comment needs a thread reply; a page-widget obligation needs a version recording its answer. Resolving a thread, editing a draft, or moving a card requires no answer, but the agent still receives the event. A draft edit or card move’s label clears when a version records or replaces it; inside a thread message, it clears when the agent next writes there or the thread resolves. A choice with a Done button gets no label until Done submits it.

Thread readings

A thread appears in several places at once: its card in Threads, its entry in the margin, its row in the Page Map, its row in On me, and its line in an activity feed. Each place says the same thing about it, so a thread never goes by two names or shows two statuses.

What it says Where it shows
Its name: the title, else the words of its opening message, else Drawing Threads, On me, the margin, the Page Map, an activity feed
Its status: Your turn, On it, Still to do, Waiting, or how far the agent has got with the latest update Threads and the floating panel, as the card's status; the margin and the Page Map, beside its name
How far the agent has got with an update: Queued for Claude, Up next, Replying, Not answered the message itself; the margin and Page Map entries
How many of the agent's messages the user has not read Threads, the margin, the Page Map
An unsent reply or rewrite its box, wherever the thread is open

On me and the agent’s list

The On view gathers outstanding work across the page, using the obligations, to-dos and workflows defined in How it works. A status sentence alone creates no obligation.

List What belongs there
On me Open obligations: each widget that asks, on the page or in a thread message; each agent message sent with --obligation; and each update the user needs to send again.
On Claude (or the attached agent’s name) Updates still owed a reply or a stamped revision, and open agent to-dos.
Done Each list’s finished records: answered or withdrawn obligations and ended to-dos. User decisions appear under On me; answered conversations under the agent’s list. A decision recorded in a revision finishes the widget’s record, without a duplicate update in Done.

On the page, an item On me is answered only in the widget or thread that asks it, and Leaf adds no control of its own to end one. A widget’s obligation is answered by the actions its x-awaits declaration names, such as a pick, or the Done a multi-select choice offers as its own control. A question in a thread is answered by the user’s reply there or a settling reaction, such as 👍. The agent ends its to-dos with leaf task end, and records the same way an answer the user gave elsewhere, such as in chat. Done history records the outcome, including withdrawn obligations and failed or dropped to-dos.

A thread’s attention identifies which side it awaits, using its updates, questions, and to-dos. The page-wide lists collect that work across threads and widgets. While a thread about a decision awaits the agent, its unanswered update represents the work on the agent’s list; the decision returns to On me when it needs the user again.

What the panel's line says

The panel's comment field, while empty, is Leaf's one line of words about the page. It says one thing at a time, the first of these that applies:

Reading Example
An error about no particular box, until the user next types Couldn't load v3
Where words go, while the caret is in the field Comment on the page, Reply in this thread
Words selected on the page, which a press on the field or c comments on “the queue fills”
A notice, or a walk's position while the user stays on its stop Updated to v4, Thread 2 of 5
The mode the user is in, which the ✕ at the row's end leaves In Draw mode
The page's status running the browser suite

With a thread open, the field is that thread's reply box. It says whose turn it is beside the leaf, such as Your turn, and Reply with the key that enters it at the line's end; a notice takes their place for its four seconds, and a walk's position follows whose turn it is.

A middle dot joins separate facts, as in In Draw mode · Thread 2 of 5, and a dash attaches a detail to the fact before it. Only words the agent wrote, such as the line it gave its work, read in its voice; what Leaf says itself, such as Stopped 3m ago, is set in italic. Words the user is writing hide the line, while screen readers still hear notices and changes of status. A press the line offers, Reply or the selected words, reads in full ink with the key that makes it, and everything else reads dimmer. The leaf and the tab's icon keep the status's colour throughout, and the leaf's menu holds the status's full sentence. A folded panel shows notices beside the leaf.

Status readings

The panel's line shows the page's status when its comment field is empty. The leaf and the tab's icon take the status's colour, and the leaf's menu holds its full sentence, with the step the harness reports, such as Thinking or Using a tool. All pages shows each neighbouring page's status the same way.

Status What it means
The leaf alone, in the working tone The agent is working, or has just received an update, and has not yet said what it is doing. The update's own label says Delivered.
The agent's line, such as running the browser suite The agent is working, and this is the latest thing it said it is doing. The menu's full status says how long ago it said it.
Approval needed in the terminal, Input needed or Question waiting The agent's harness is waiting on a dialog in its own window. The page can't answer it, so the status says to answer it in the terminal, ahead of the agent's line.
Ready — select text to comment The agent is taking updates. One still on its way to the agent says so on its own label, and the menu's full status counts it.
Stopped 3m ago The turn in which the agent said what it was doing has ended, and it has not started anything since. It still takes updates. Pointing at the status shows its last line.
Last checked in 20m ago The agent has not renewed what it said it was doing for 15 minutes. It still takes updates.
Away Nothing is taking updates for the agent right now. Updates are saved, and its next turn picks them up. A message Leaf sends a Claude Code session as an update arrives can wait there for the user's approval.
Not answering — nudge the terminal Nothing is taking updates, and one has stalled: it has waited two minutes, or the turn it reached ended without answering it. A message in the agent's terminal starts another turn.
Not on this page right now The session attached to the page has exited. Another session can take the page over.
Done with this page The agent has closed the page.

The server chooses the status from what the agent last declared and started, and from what it observes of the agent's session, turns and watchers; every tab and leaf page state read that one result. Page activity gives the rules, and the conversation loop says when the agent writes its line.

Notices

A notice stands in the panel's line for four seconds and is announced to screen readers. Simultaneous news shares one notice, such as Not answered · New on me. Some news is only announced, since something on the page already shows it: an agent message the user hasn't read, which the On me mark's dot and its margin marker show, and the user's own gesture, which the widget draws where it was made. Opening a page announces only unread agent messages, not its existing activity. The agent starting or stopping work is no notice: the status in the same line says it.

Notice When
I shortened the lede., Edited: …, 3 replies in 2 threads Announced only: an agent message the user hasn't read arrives, or one is edited. One message speaks for itself in its opening words, including anything it asks of the user.
New on me, 2 new on me Something new waits on the user, such as a question a reply asks or a decision a revision adds.
Not answered, Interrupted mid-answer The harness reports that a response failed or was interrupted.
Updated to v4 A new revision replaces the page in place.
Moved to Done, Undid: Moved to Done The log accepted the user's gesture, which is announced only, or its undo.

Navigation

Leaf's shortcuts act where focus is. A thread, its passage and its margin card count as one place. Text fields keep typing and caret movement; native controls keep their activation keys. Escape leaves one interaction, browser Back returns to a reading place, and Undo withdraws a recorded action.

Intent Route
Reach a control Tab / Shift + Tab; Enter activates it. A tab strip uses arrow keys.
Move through threads t advances; Shift + t goes back. Past either end, the walk comes round to the other.
Move through On me, the items waiting on the user m advances through them; Shift + m goes back.
Choose a destination g opens hints and the Go-to map.
Find page text / opens search. Enter chooses a match; n / Shift + n then walk matches.
Link to a section The link mark beside a heading, shown under the pointer or by a tap, copies the page's address of that section. On the section, Enter copies it.
Find a thread or message With focus in Threads, / opens search. Arrow keys move through result rows; Enter opens one.
Read further j / k scroll a little; d / u move 60% of the focused reading area.
Leave or return Escape leaves one interaction. Browser Back / Forward traverses reading history. z, or Undo in the leaf's menu, takes back a recorded action.

? opens the command reference for the current context; menu rows show their own shortcuts. On touch screens, use thread titles, markers, Page Map and the leaf’s menu. The movement rules distinguish walks that wrap from lists that stop.

Named destinations and visible hints

The complete Go-to map

Press g, release it, then type the route; uppercase means Shift plus the letter. Named routes are fixed. Lowercase hints are assigned to visible controls for the current view. Only applicable routes appear.

After g Destination or action
T Open Threads and focus its selected thread; close Threads when it is already open.
M Open or close On me.
L Open or close All pages, when neighbouring pages are available.
P Open the searchable Page Map.
V Open Versions, when version history is available.
p Return to the page, letting go of the current target or margin card. A panel covering the page must close first.
g / G Go to the top / bottom of the page, or of the panel covering it.
k / j With a thread card or title focused, place that thread at the top / bottom of its list.
z Scroll the current item to the top, keeping focus and selection. Bare z is Undo.
u Go to the first unread message, from the page or Threads. Bare u scrolls up.
i Resume the last writing place, when one is remembered.
v Restore the last selected passage, when one is remembered.
Visible hint letters Activate the labelled margin entry, tab, control or link, or open a disclosure at its summary. A hint letter lasts only for the current view.

Lowercase m, t, h and f filter hints to margin targets, thread controls, hyperlinks and folds (collapsible sections). Further letters choose a target: g then t filters thread controls; g then T opens Threads.

Tab / Shift+Tab move through hints; Enter takes the announced hint. Escape removes the last letter, then the filter, then cancels. There is no timeout. Editors keep typed letters.

Reading and text search

Scrolling keys follow the focused reading region

j / k and d / u scroll the focused reading region: the page, a pane, or the panel’s view. The Go-to map covers page edges, first unread message and item alignment.

Searching text and returning to reading

/ searches page text, or finds threads and messages when focus is in Threads. Search uses the panel’s main field, labeled “Search page” or “Search threads”, and keeps the unfinished comment and its caret for when search closes. The match count and arrows share that bottom row. In page search, Tab / Shift+Tab and the search arrows cycle matches; Enter or a tap on the marked match selects it. n / Shift + n repeat an accepted page search. Thread-search results use the panel’s row navigation. Escape cancels page search and restores the earlier focus; in Threads it clears the query, then closes search. Editors keep letter shortcuts.

Threads and work waiting on the user

t / Shift + t walk open threads in page order. Focus on a thread or its accompanied passage makes that thread the origin. Moving elsewhere changes the origin; Leaf keeps no separate “last thread” cursor.

Resolving and replying

r resolves the focused open thread. A thread opened from Threads advances to the next open thread in page order, or the previous at the end; with none left, it returns to the list. A margin card moves on to the next thread at its passage, or the one before, and closes onto its passage with none left. An embedded thread folds in place.

Search, replies, and undo
Sequence or state Current result
Resolve the only shown thread The next destination comes from all open threads, independently of a search. When no open threads remain, the panel returns to Threads.
Resolve a thread found by search The search can show both open and resolved threads. Resolving a thread opened from that list still advances through open threads in page order.
Type r in a reply box The box receives the letter. Escape returns to the thread before its resolve shortcut applies.
c, compose, send A reply leaves focus on its card or title; a page comment leaves it in the panel’s field. Escape keeps an unfinished draft.
Undo a resolution The thread reopens. If the panel has returned to Threads and the reopened row is shown, focus returns to it. If another thread is now open, that view stays put. An embedded thread retains its place.

Panels and Escape

Escape's next step depends on focus

A comment composer returns to its element; a reply box returns to its thread. In Threads, Escape clears a search before leaving it. Page-side selections, targets and margin cards can unwind while a desktop panel stays open. A covering panel must close before the page behind it is accessible.

m, c, Escape returns to the obligation and its option keys; another Escape lets it go. Commenting from an option or aiming at that obligation has the same return. A visual comment returns to its current response proxy. A whole-page comment stays in the panel’s field; closing a comment on selected words clears the selection.

Opening All pages or On me replaces the panel’s current view. Escape closes the new view rather than restoring the old one. Pointer and keyboard entry give the view the same Escape parent.

Back and Forward

A successful navigation step to a destination that is not fully readable adds a return stop where the user stood, so Back returns to the item they were on: after t then m, Back returns to the thread, and Back again to where they were reading before t. A fully readable destination adds no stop.

Which actions create a history entry?
Action History behavior
t, m, a marker, or Page Map reaches a hidden or clipped destination A successful navigation step pushes an entry. Changing focus alone adds none.
Follow a #fragment link The browser supplies a history entry. Leaf reveals the destination's enclosing tab or disclosure and lands on the named element.
Select a root page tab The switch saves the outgoing reading position and adds an entry; Back / Forward returns between views. Embedded tabs add no entry.
Scroll, search page text, align with g then z, open a panel, Escape, or resolve These actions add no reading-history entry themselves. Back neither undoes a resolution nor unwinds a panel.
Back / Forward returns Leaf restores the view and restores focus or selection where the saved nodes survive and remain visible. A newly hidden destination is revealed again. A newer gesture cancels a delayed return.

Enhanced return handling uses the browser’s Navigation API. Other browsers retain native traversal and fragment landing.

Phones and touch screens

Touch users can read, comment and operate widgets. Leaf’s page commands have direct gestures or visible controls; authored widgets supply their own routes. Narrow windows describes how page regions stack.

The panel and its menu

The panel fits a narrow window with space at its edges. Its row holds the leaf, a comment field showing agent status, and the On me count beside its icon. A temporary notice replaces the status words.

The leaf opens its menu, the first tab beside On me and Threads. It includes Search page and Page Map under Navigate, Undo, and Select mode, Draw mode, Design mode and Hide annotations under Annotations. Decisions appear in On me and in their widgets. An active mode or search names itself in the panel and provides a ✕ exit. Search arrows appear beside the match count; tapping the marked match selects it.

Comments, threads and widgets

Select words to quote them in the panel’s field; tap the field to open a comment below the block. For a whole table, figure or other element, use Select mode.

Where the margin cannot hold a rail, markers appear as pins on their blocks. Tapping a pin highlights its passage and opens its thread card. Threads opens above the panel’s row. Hide annotations hides the pins.

On a touch screen, a board at most 640px wide shows a Move to row on each card, reaching offscreen columns without dragging.

Touch coverage and testing

  • Whole elements. Open the leaf’s menu → Annotations → Select mode, then tap the target. This opens its comment composer without activating the target’s controls.
  • Commands. Menu commands and direct controls provide touch routes; the panel and reply fields suppress keyboard hints for a coarse pointer.
  • Exits. The panel’s ✕ leaves an active mode, search or target picker. Within the picker it first removes a typed hint prefix.
  • Hover detail. Authored hover explanations need a touch-accessible alternative; keyboard and hover behavior alone do not establish a touch route.
  • Layout. Page-authored controls and diagrams still need review at narrow widths for target size, legibility and reachable content.
  • Device coverage. Automated touch journeys use browser emulation; they do not establish real-device behavior.
