Release notes

Two items change stored data. Four affect behavior at request time.

How this queue was ordered

Data changes lead, followed by customer-visible paths and workers.

Details

Authentication retry

Status
Ready for release
Owner
Identity platform
Reach
Web and mobile sign-in

The client retries one expired-session response after refreshing its credentials. Other authorization failures return immediately.

Concurrent calls from the same tab share one refresh request. Waiting calls reuse its result when a busy page reaches session expiry.

Release evidence

  • An expired session refreshes once and repeats the original call.
  • A revoked session returns the first authorization failure.
  • A failed refresh leaves the original request unsuccessful.
  • Five concurrent calls share one refresh response.
  • The retry preserves the original idempotency key.
Inspect the remaining concern

The mobile client waits up to three seconds for the shared refresh. The release check must confirm that a slow network still surfaces the sign-in screen instead of leaving the request pending.

Rollback

The client flag can disable the retry without changing session or credential data. Requests then follow the previous single-attempt path.

Cache migration

The deploy copies active entries to the new key format before readers switch. A failed copy leaves the old keys authoritative.

verify counts

Receipt email

Refund receipts now show the original charge and the refunded amount in the settlement currency.

  • Partial refunds keep the original order number.
  • Repeated refunds list each settlement separately.
  • Failed sends remain available for retry.

Ledger export

The exporter writes numeric amounts without display formatting and records the schema version beside each batch.

Rollback path

Readers accept the previous schema until the new batch is verified.

Order search

Archived orders follow the existing filter instead of disappearing when a customer narrows by status.

Pagination retains the filter on every subsequent request.

Billing reconciliation

The close job compares settlement totals with the ledger before it publishes the monthly report. A mismatch stops publication and keeps both source summaries attached to the run.

Samples checked

  • A partial refund posted after capture.
  • Two refunds against one charge.
  • A settlement converted into the reporting currency.
  • A late adjustment received during the comparison.
Open difference

One legacy invoice rounds tax before currency conversion. The sample must establish whether it belongs in the old reporting path or needs a corrected ledger entry.

Webhook delivery

Delivery attempts retain the event id across retries. Partners can deduplicate a delayed event without provider-specific headers.

The retry schedule and signing secret remain unchanged. The release adds the stable id to the documented request body.

Review closes when the cache rollback and billing sample are resolved.
