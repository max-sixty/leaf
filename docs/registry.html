Registry keys

An element declaration begins as JSON Schema. Its x-* keys tell Leaf how the element reads, renders, changes, and joins the collaboration loop. Choose a key below to jump to its summary. Longer contracts open in place.

This reference is generated from the registry's $keys, the same entry an agent can query in a page's merged registry.json. Start with the extension guide, or read the complete package contract.

x-awaits

The widget asks the user for input while its authored attributes match when.

Full contract

The ask's id is widget:<source-id> and does not change; a framing x-question-context supplies only the prompt words and where travel to the ask lands. value names the x-state verb whose state is the typed answer: the verb's record value, or, where it has no record, the detail of its latest action still in force. A verb that keeps state per member unit gives a map from each unit to its value. answered declares when the ask is complete, separately from value: a partial value can exist while the ask is open, and a completed empty value is still an answer. Core publishes one record per ask with source, prompt, answer {value, event}, status and next_actor. An ask once registered stays answered or withdrawn after when stops holding; an element that never matched when creates no ask. A restated event starts a fresh request. A comment in the widget's thread box (x-thread-seat) makes the agent the next actor without answering the ask. A widget frozen into a thread keeps its ask after that thread closes, with no next actor. A quoted widget (x-exhibit) registers no ask. all names the outcome one banner control can give every ask of this kind at once. Asks and to-dos are separate records, and the Questions list reads asks directly.

x-bound

The element holds its own height and scrolls inside it, so a long log or feed never grows the page: start opens at its first line and end follows its newest entry while the user is at the end, and stays where the user scrolled back to otherwise. An authored occurrence may state or override it with data-bound=start|end; delivery paints it into the served document as data-lf-bound.

x-content

The required content model: markup (the author's markup), members (only this element's declared member elements), data (one <pre> containing text in the notation the description names), or empty. A data body uses <pre> to preserve whitespace without CSS, with & < > escaped as &amp; &lt; &gt;.

x-data

The widget's named external-data inputs.

Full contract

Each input names a $data.contracts contract and the declared canonical string attribute whose authored value is this page's source id. The input follows the source's current value. An optional source attribute leaves that input absent; watchData delivers null. Several widgets may bind the same source to the same contract. A document binds a source to one contract. Later documents may replace that binding; each captured document reads the current value against its own declared contract and reports incompatible values as source errors. A module subscribes by widget and input name, never by a package-owned source name.

x-example

Authored markup exhibiting the widget, valid against the merged registry: an agent reads it with the element declaration, writes from it, and the lint refuses one that does not validate.

x-exhibit

The element displays quoted content: nested widgets are not interactive, and nested asks do not enter the user's Questions. Modules check quoted(el) before enabling input. The theme suppresses interactive styling inside quoted content.

x-face

Child selectors, each :scope > followed by a tag, classes, or both (:scope > lf-new, :scope > .lf-shotrail), naming light-DOM children whose painted boxes are part of the element's own appearance rather than separate things it contains, such as a suggestion's tinted slots or a screenshot's caption rail.

Full contract

A margin pin whose target is this element may sit over these children, as it may over the element itself, but still keeps off their words. A pin keeps entirely off every other box inside the target that paints its own area, because a pin over such a box reads as belonging to it, as a choice's pin over its first option's card would read as that option's. Declare a child here only where a pin over it reads as the whole element's.

x-height

The height, in CSS pixels, the page reserves for the element before its module draws: the declaration's number, or an authored occurrence's data-height, which overrides it; true declares no number, so only an occurrence's data-height reserves.

Full contract

Delivery paints it into the served document as data-lf-height, and wherever the runtime runs the theme holds the box to it from the first paint until the module marks the element drawn (lf-rendered), when the box becomes the drawing's own. Declare it on a widget whose drawing cannot be sized from its markup before the module draws. A module that can draw to any height, as a chart's can, draws at the stated one, so nothing moves when the reservation ends; one whose content has a height of its own draws that, and the reservation is the author's estimate of it. A failure takes the height of the message it shows.

x-history

true: the module renders the page's history, so a page whose markup holds one is served the history reading beside its state and a page without one does not pay for it.

Full contract

The reading is the newest 50 logged events, newest first, each naming who acted, what they did, the thread it belongs to and that thread's title, whether a later undo took it back, and for a widget gesture the words its ids had in the document it was made in, so a later version rewording or removing what was chosen leaves the row as made. The module reads it through watchHistory.

x-initial

The rooted path of a captured classic JavaScript bundle registering the widget's synchronous initial renderer with document.documentElement.lfInitial.register(tag, render).

Full contract

Delivery inlines each used bundle once in the head, buffers each outer host in an inert template until its source is complete, and inserts and draws it in one synchronous turn, nested hosts deepest-first. render(host, {tabStore, offer, offerElement}) builds the instance's real markup using authored values and tab-local mechanical state; it performs no network or asynchronous work and returns the structure the behavior module adopts with initialRender(host). The widget loader imports that same bundle before the behavior module for later revision and thread arrivals, only where it has not already registered. The coordinator preserves the original authored markup and node routes before rendering, so source comparisons and semantic readings do not consume the drawing. Requires x-upgrade: true and excludes x-prepaint.

x-inline

The element sits inline among the words around it.

Full contract

The render gate therefore does not require it to have a width of its own, and does not apply the rule that a block widget must stand where a block is allowed.

x-instructions

Author instructions for using this widget, read after selecting it and before writing markup. A flat nonempty string, separate from its short discovery description and its structured schema.

x-language

The attribute that names a code language.

Full contract

Its value must be one of $languages.names, the one list of languages the page highlights, so a new tag that takes a language needs only this declaration and no code of its own to read the attribute.

x-measured

A scalar in authored content pinned to one x-data input's run receipt.

Full contract

input names the widget's data input and run its required nonempty receipt attribute. When that source holds a different run, page check warns that the authored measurement is stale and page state reports it too. A source rewritten with the same value counts as a new run; a measurement's age alone does not make it stale.

x-name

The attribute whose value is this tag's title: what the page calls one of these elements when it names it away from itself, as the activity feed does for where something happened.

Full contract

Leave it off where the authoring contract already titles the element: a section by its heading, a disclosure by its summary, a titled member by its leading <strong>. Declare it where an attribute is the title instead, as a column's or a tab's label is. An attribute the element merely shows first, such as a metric's value or a chronology entry's time, is not its title.

x-owners

The element declarations that may directly own a Leaf element.

Full contract

Read from an owner, this defines which direct child Leaf elements are its members rather than nested elements it merely contains; a gesture the owner takes on its whole box stops at those members.

x-patch

How a revision reaches an upgraded widget the user has open.

Full contract

By default its module owns everything under the element, so a revision that changes any of the widget's markup replaces the whole widget and rebuilds whatever the user had open in it. members says the module builds its own controls beside its members, leaves them where the author wrote them, and reads nothing of them but their attributes: while a revision keeps the element's attributes and each member's tag and attributes, in order, it edits inside the members in place and the widget stays. Requires x-content: members and x-upgrade.

x-prepaint

Markup an upgraded element shows at its first paint, before its module draws: one element with the structure the module will draw, holding words that give it the size the drawing will have.

Full contract

Delivery writes it into every occurrence in the served document, as the element's first child marked data-lf-prepaint, so the browser lays the widget out from its real structure and wraps it as the drawing will, instead of reserving a height computed from line heights. The theme keeps that space and paints none of the prepaint markup, and a reading without the runtime hides it. The module removes it in the same step that draws its replacement, so nothing moves, and draws by filling in a copy of the same markup, so this declaration is the only statement of that structure. {"as": tag} takes the named widget's prepaint, for an element that first paints as that widget will appear inside it, as a command with no readings seat draws one at its head. Write the markup exactly as the parser reads it back, with every element closed, because delivery inserts it as written and an unclosed element would take in the occurrence's own children. It carries no id, no custom element, and no script, since every occurrence gets a copy. Declare it on a widget whose drawn structure is fixed while its values come from the log, as a command's outcome and count tiles are; a widget whose rows depend on the log has no fixed structure to write here.

x-question-context

The element frames the asks nested in it.

Full contract

Its leading direct heading supplies their prompt text, and travel to one of those asks lands on the element. It never changes an ask's identity, answer or completion, and never merges asks from different sources. Where frames nest, an ask uses the nearest. One frame may hold several asks, each keeping its own widget:<source-id> identity. lf-ask is one element that declares this key; a widget that asks on its own needs no frame. When Leaf names the element's kind, it calls it a question, unless the element's x-word module returns another label.

x-reading-role

The structural role an element supplies.

Full contract

The only role is pane: a labeled reading region whose body scrolls on its own while the workspace is full-height. A pane holds exactly one body element, optionally preceded by a direct native header and followed by a direct native footer. Validation of roles reads this declaration rather than tag names, and a pane's content stays markup, so packages can contribute panes under their own tag names without a fixed list of allowed parents and children. A pane requires a string id and a string label; the label names its accessible region, and a visible heading belongs in its authored header.

x-refers

A map from attributes whose values name another element to their target contracts.

Full contract

An empty contract accepts any element id (an option's for). A typed contract names a shared registry map with via and an equality predicate with where; page check then requires both an existing id and a target tag whose declaration in that package-owned map matches the predicate. This lets a package distinguish a goal, worker, or evidence reference without Leaf knowing those roles or tags. A typed contract with owns: true says the referrer fills its target, as a command fills the readings seat it names: page check requires the target in the referrer's own document, and every element there that the predicate selects named by exactly one referrer. A keyed contract {tag, key} names a member by an attribute rather than an id: the tag element whose key attribute holds the value, inside the referrer's own nearest owner of the tag key is unique within, which tag declares in x-unique (a playground preset's setting names a control of its own playground by name); page check and message markup refuse one naming no such member. In the browser a declared attribute is what a module hands navigateToDatum and the experimental indicate to reach the named widget, which each resolves in that same owner for a keyed contract, and otherwise in the owner's own authored document first (its message's markup, for a widget in a reply) and then in the page.

x-resident

How an element sits in the margin when it is the only occupant, or one occupant, of a column page's first aside.sidebar.

Full contract

The only value is map, a contents map: where the margin has room and the pointer is fine, such as a mouse or trackpad, it shows as a spine in the left margin and reveals its labels over the page. Delivery writes the declaration into the served document as data-lf-resident, so the margin layout reads it rather than a widget's tag. A thread message has no margin, so delivery does not write it there.

x-retired-when

On a member: the outcome of its owner's decision that removes this element from the page, as accept removes a suggestion's lf-old.

Full contract

Requires x-owners. The outcome is a value of the outcome detail field on the owner's one deciding verb, so only one decision can be in force. The layer renders the decision itself and follows the log in both directions. Reconciliation writes data-lf-state="<outcome>" on the owner and data-lf-retired on the members that outcome removes, and takes both off when undo or a retraction withdraws the deciding action; one theme rule hides the marked members. No module has to do any of this, though a module may write the same attributes earlier as part of its own gesture (renderRetired). These attributes are rendered output for CSS, export, and checks; code that needs the decision reads the publisher's explicit outcome rather than the attributes. The file-side reading takes the decision from the log, and once the log decides it, page check allows a revision to drop the member's ids. page check --render reports a removed member that still shows words, and a mark the log never decided.

x-says

Attributes whose values render as selectable text, and where that text appears.

Full contract

after places the text inside the element, after its content and before trailing controls. before places it at the start, before content and controls; multiple before attributes render in declaration order. The runtime creates text nodes so the user can select, quote, and comment on these words; CSS content: attr() cannot provide that.

x-shadow

The module renders the page's words into an open shadow root. Leaf's passage reading, selection capture, and every lookup by id reach into it. The render gate reports a shadow root on an element whose declaration lacks this key.

x-space

The default width an element takes in a flow wider than the prose measure: column keeps that measure and starts where the prose does, for an element or idiom whose content is read as lines of text or that frames prose (an ask, .callout), and it widens to the widest allocation among its own blocks; wide takes the vocabulary's shared capped evidence width; available takes all room the page shell can give after enclosing frames, chrome, and actual margin residents.

Full contract

An element that declares none fills the box it stands in. The declaration says nothing about how the package arranges content inside that allocation. An authored occurrence may override the default with data-width=wide|available; delivery paints that choice into the served document as data-lf-space and the theme allocates it without moving the prose axis.

x-state

What x-state declares, once per widget that has state: for each verb, the unit of the widget's state it changes, who writes it, and either its recorded effect or the schema of its unrecorded detail.

Full contract

A recorded effect's payload follows from the effect kind and the destination attribute, so it declares no detail schema or field mapping of its own. A verb is the user's unless it declares writer: "agent". The user writes a user verb through the page, as action events; the agent writes an agent verb with leaf page report, as report events, so each [widget, unit, verb] key has one writer. A user verb may declare a child element it creates (creates). An agent verb needs a record form other than body, because a report changes declared state and never the page's words, so it never changes what the passage reader reads. An agent verb may declare report: true to require a non-empty detail.text, the report's short news for a person, which the report feed shows as written instead of composing it from the widget, verb, or field names. The runtime marks a report on the page as soon as it is in force (data-lf-reported); it stays only until a version answers it, as $report says. Each verb holds its own state: for each [widget, unit, verb] key, the latest action that has not been taken back replaces earlier ones, and different verbs on the same unit coexist. The framework combines those latest actions with the typed authored values and gives each widget its complete state through renderState, keyed by verb. The same declaration drives POST validation, replay of the complete state, inspection, the runtime's readings of user actions and reports, and the state half of a version diff. When an admitted action makes the widget's x-awaits answered condition hold, Leaf records meaning.answer on the event. Its value is the thread named by the widget's authored resolves attribute in the document the action was sent from, which the answer closes, or null when the answer closes no thread. A decision whose outcome is the widget's x-withdrawn-as value also records null, and the page then reads as if nothing had been proposed. A past action keeps the [widget, unit, verb] key it was admitted under, even after the widget leaves the page. One detail field name is reserved: outcome, on the one user verb that decides which retirable members leave the page (x-retired-when). $state documents units, creates, and record forms.

x-text-format

Text format: inline-markdown formats this element's direct text nodes; markdown renders its exact data body as safe block Markdown.

Full contract

A body record retains Markdown source while passages read visible words. Its existing element children remain HTML. The browser formats those words with the shared safe Markdown parser, while file-side passage and revision readings use the same visible words. A generated child with this declaration interprets the user's line breaks as hard breaks; source HTML line wraps remain ordinary whitespace.

x-thread-seat

The module places a thread box (threadBox) in each matching Leaf element, chosen by the authored, static attributes in when; an attribute that an x-state value record writes cannot satisfy when.

Full contract

The box shows, as text, the threads anchored exactly to that element, read from the whole log; the Threads panel keeps the full interactive view. A matching element inside thread markup or quoted content gets no box. If the widget also asks a question (x-awaits), the box is where the user answers it in words: while a thread there waits on the agent, the ask leaves the user's Questions list, so the user does not see it twice. That comment does not answer the ask. The widget's state is unchanged, its controls still work, and the ask still reads as unanswered. hold is the label of a second send control in the box, whose comment carries holds, naming this widget. A held comment starts a thread like any other comment in the box, and the control stays available after other threads have started there. The widget is held while that thread is unresolved; resolving the thread releases it, and undoing the resolution restores the hold in one step. Removing the widget removes only the box, not its threads.

x-thread-surface

The upgraded widget can show Leaf's comment box and threads inside itself, beside the exact data items (datums) they are about.

Full contract

Leaf registers the widget when it upgrades and retires it when it leaves the page. On each reconciliation pass Leaf calls the element's own threadOutlets(targets, {signal, collection}) with one ordered batch of the admitted targets anchored exactly to its items, and the method returns for each target an element to place it in (an outlet), or null. Leaf maps each outlet to its thread or to the open comment box and controls where it is placed and how long it stays. The widget reads its registration with threadSurface(element): update() says its seats changed, and open(datum, {origin}) opens Comment on one of its items. Leaf owns anchors, drafts, response modes, sending, thread rendering, reply and reaction state, settlement, focus, receipts, and the fallback to the margin. A placement holds that comment box or thread in the widget for the current reconciliation pass only. An item that is not loaded, filtered out, collapsed, outdated, or otherwise not shown gets no placement; its threads stay in the Threads panel and fall back to the margin as usual.

x-tone

The attribute that names one of the layer's semantic tints, held to $tones.names, which the theme has a rule for.

x-unique

A map from attributes whose values no two members share within one owner to that owner's tag.

Full contract

page check and message markup refuse a member whose value repeats another's inside the same nearest enclosing owner of that tag, as two controls of one playground sharing a name or two choices of one control sharing a value. A keyed x-refers contract names members by such an attribute, so it always names one.

x-upgrade

A module at widgets/<tag>.js enhances the element in the browser, imported where a page's markup carries the tag rather than for the whole layer. page init refuses a layer declaring it with no module beside it, and the render gate a module that defines no element for a widget the page contains. Required.

x-verbatim

The upgraded element keeps its authored words, and keeps nested upgraded widgets in their authored order with their identity, so the passage reader can quote those words.

Full contract

Each nested upgraded widget keeps its own declarations about its words and boundaries, so what it generates is not a claim made by the wrapper. Without this declaration the passage reader treats the widget as opaque, since its module may insert or replace words. The render gate refuses a page where the wrapper's own words changed or a nested widget was removed or reordered.

x-views

true: the element shows one of its members at a time, as a tab set shows one panel, and its module opens it on the member the runtime names (openingView) and records each member it shows (keepView).

Full contract

The runtime opens it on the member holding the element the address's fragment names, else on the member this browser tab last showed, else on the first; a reload puts the member last shown before the fragment's. Delivery paints it into the served document as data-lf-views, and before the first paint Leaf marks the member it will open data-lf-opening, so the package theme can show that member alone until the module upgrades the element.

x-visual

How a rendered picture exposes stable Comment targets.

Full contract

whole anchors the picture on the authored widget. Every declared provider also supplies its own visual surface for whole-widget aim and marks, so chrome paint stays above the widget's drawing. For {parts: ATTR} or {prefixes: [PREFIX, …]}, its module calls registerVisualParts(source, read) once; read returns the complete current {id, element, label, surface?} inventory. Core admits only ids authored in ATTR or, under prefixes, any longer id one of them begins, such as commit:3f2a under commit:: a picture drawn from data whose parts the author cannot list declares their kinds rather than enumerating them. Core derives token lookup and deepest-part hit testing from that inventory. surface defaults to element and may name one descendant whose native paint excludes decoration from the contour. It changes paint only: element remains the semantic hit and travel target. Marks and aim follow an SVG surface's painted geometry primitives; a surface with none, and every other element, uses the shown box. Targeting a mapped part stores its id as anchor.visual while the widget remains the semantic seat. A missing token or registration detaches on replay rather than widening to the whole picture. A visual that draws its parts over time passes registerVisualParts(source, read, {reveal}): reveal(id) synchronously settles on a state whose inventory holds that declared part, even when it is already visible, cancelling any pending replacement that would retire it. A declared part absent from the current state then places its threads on the whole picture, and travel to the part, whether a thread anchored there or a module's navigateToDatum, calls reveal before landing on it. The registration's update() signals any rendering or geometry change, including an in-place attribute or style change. The render gate validates every record, requires each authored token to resolve, in the current state or after its reveal, and refuses a registered id its prefixes do not admit. A {parts: ATTR, all: TOKEN} declaration admits the complete registered inventory when ATTR is TOKEN, preserving a whole-picture target when ATTR is omitted. A {parts: ATTR, complete: true} declaration also refuses a nonempty authored list that omits a registered part; omitting ATTR keeps the whole picture as one target.

x-withdrawn-as

A declared deciding outcome that declines the proposal.

Full contract

It answers the ask without closing the widget's resolves thread. A revision may also remove an unanswered proposal directly, whether or not it has retirable slots; historical ids do not veto the edit.

x-word

The module supplies the widget's type label through lfWord().

Full contract

For example, lf-suggestion returns "insertion", "deletion", or "rewrite" according to its children. Leaf uses this label when referring to the widget in a panel row or comment anchor. If the widget has not upgraded, returns no label, or does not declare x-word, Leaf calls an x-question-context widget a question; otherwise it uses the tag name without its prefix. The same declaration lets the module supply descriptive text through lfSays(), for widgets whose text nodes alone do not convey their structure, such as a rewrite's old and new text. If no description is returned, Leaf reads the element's text.

x-work

true: the agent may open its own to-do on this widget with leaf task open even when the widget holds no unsettled update, and the runtime shows the to-do beside the widget's authored markup.

Full contract

Only a block widget whose x-content is markup may declare it. Once opened, a to-do on a page widget shows at the page edge through its target's margin entry, even if a later layer drops x-work. Markup content does not imply x-work, because markup can itself be a control its owner uses, or sit in a hidden panel.
