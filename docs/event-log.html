how it works

The event log

Leaf appends comments, widget actions, agent replies, reports, and version records to events.jsonl. Earlier records remain when an action is undone or retracted.

A widget's state starts with its authored markup. Leaf keys each action by [widget, unit, verb]: the owning widget, the part of its state being changed, and the operation. For each key, the latest action that has not been undone or retracted sets that part of the state. Repeated choices in an options group change the same selection unit, so a new pick replaces the previous pick.

This page explains the mechanism. The rules themselves live in the events contract and the package contract's User state, which agents and package authors read.

Event validation and widget state

A widget submits an action. Leaf validates it against the package's registry declaration and appends it to the log. Leaf derives widget state from the authored initial values and logged actions. Packages declare their own verbs; Leaf processes those declarations without package-specific code.

Try actions and undo

The sample below is a complete Leaf page with a log of its own, and its feed lists that log newest first. Open Show activity, then type After the canary is healthy into Another option, and press Enter: press the new-updates notice to reveal an add and then a pick. Pick Later. Then press z three times. The first press brings your own option's pick back, the second leaves nothing picked while your option stays, and the third removes the option. Press the activity notice to read the changed history; it waits so arrivals never move what you are reading. Reset starts the sample over.

Verb declarations

This is everything lf-options tells Leaf about its three verbs and when its question counts as answered. 

"x-state": {
  "choose": {
    "unit": "widget",
    "record": {"kind": "attribute", "attr": "chosen"}
  },
  "add": {
    "detail": {"type": "object",
               "properties": {"option": {"type": "string", "pattern": "^[a-z0-9][a-z0-9-]*$"},
                              "text": {"type": "string", "minLength": 1}},
               "required": ["option", "text"], "additionalProperties": false},
    "unit": "option",
    "creates": {"child": "lf-option", "words": "text"}
  },
  "answer": {"detail": {"type": "object", "additionalProperties": false}, "unit": "widget"}
},
"x-awaits": {
  "value": "choose",
  "answered": {
    "choose": {"when": {"multiple": [false]}},
    "answer": {"when": {"multiple": [true]}}
  }
}
The verb's name, which the widget sends as the event's action. One unit for the whole group, so every pick uses the same coordinate and a later pick replaces an earlier one. How the current selection appears in markup: chosen on each picked option. This effect also determines the payload: detail.value must be an array of owned option ids. The agent writes the pick into the next version, and page check refuses a version that contradicts it. The unit is the value of detail.option, so each added option has a coordinate of its own. The action adds an lf-option to the group, with detail.text as its text. answer is the Done press that closes a multiple group. The Question's typed answer comes from the standing choose value. A single-choice group is answered when an option is selected. A multiple-choice group is answered when the user presses Done. Undo can make the Question unanswered again.

An action's coordinate is its widget, its unit, and its verb. unit: "widget" means the widget itself; any other value names the detail field that holds the unit. A pick therefore uses [ship, ship, choose], and adding an option uses [ship, <new option id>, add]. Two actions compete only when their coordinates are equal, so a pick never displaces an added option.

The browser sent kind, revision, widget, action, detail, and attempt, its retry key. Leaf added the remaining fields. attention records whether the action changes work the agent owes. Leaf derives meaning and refuses a sender that supplies it. It keeps only what a reader without the registry could not recover: whether the action was made on the page or in a thread (scope), its fold unit, the element ids it depends on, the child tag it creates, and the operation's state definition. That definition records the operation and its allowed detail values so later revisions can tell whether the decision still applies. Leaf generates the eight-hex id; seq is the record's line in the log. This pick makes the Question's answered condition hold, so it completes the Question. null means it closes no thread; a group with a resolves attribute would name one here. An undo names the gesture to withdraw. Leaf excludes that gesture when deriving state, and both records stay in the log.

Replacing and withdrawing actions

  • A later action at the same coordinate supersedes it, as the pick of Later did. Undoing the later action restores the earlier one.
  • The user's undo withdraws one gesture of their own: an action, a resolve or reopen, or an approval. Sent messages cannot be withdrawn.
  • The author's restated: a stamped version lists element ids it deliberately rewrote, and every earlier action that depends on one of them is retracted.

Once the agent records a current decision in the markup, such as the added option as an ordinary lf-option with the same id and words, the document carries it and the action no longer changes what the page shows.

Agent-reported state

A verb declared with "writer": "agent" accepts reports from the agent. leaf page report appends a report event, which updates the widget until a stamped version settles the report. The package contract's User state gives the complete rules.

Following new events

leaf page events PAGE --follow prints every stored record, then each new record as Leaf appends it. To resume after the last printed record, pass its seq value to --after.

Typed external data under data/ is replaced in place rather than logged, so the feed does not carry it. The events contract's Following the log gives the feed's whole contract.

Where each rule is written

  • Events and threads: every event kind, undo, admission and meaning, and the change feed.
  • User state: how a package declares x-state verbs, x-awaits.answered, creates, and agent-written verbs.
  • Registry keys: the exact definition of x-state, x-awaits, and the keys beside them.
  • Layer composition: which recorded actions a re-vendored layer must still be able to read.
