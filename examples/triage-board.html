Why only the migration blocks

The deploy script writes the schema version after the post-deploy hook, and the hook exits non-zero on a warning. So the stamp never lands, and every deploy runs 0041 again. 0041 only adds a column, so rerunning it is a no-op. 0042 credits every account that was billed twice in March. Run twice, it pays twice.

Every other card is either cosmetic, has a safe retry, or affects one customer who has a workaround. None gets worse by waiting a week.
