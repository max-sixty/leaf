Sandbox rollout

The review sandbox runs each pull request's setup script before the reviewer opens it, so a reviewer starts from a working checkout rather than a fresh clone.

Step one moves the sandbox behind the runner pool. The sandbox waits until v2 of the runner image ships, which isolates setup from the host's credentials.

Step two caches each repository's dependencies by lockfile hash. A cache miss costs one cold install, about forty seconds on the larger repositories.

Step three opens the sandbox to forks. Fork setup scripts run untrusted code, so this step needs the isolation from step one before it ships.

Until then, reviewers of fork pull requests keep the current flow: a fresh clone and a manual setup.
